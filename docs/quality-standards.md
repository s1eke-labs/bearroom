# 场景质量与验收规范

本文件补充 [需求文档](requirements.md)，用于约束实现与验收结果，不描述制作步骤。整体采用萌系偏写实风格：高精细造型、柔软奶白绒面与布艺、细腻材质和真实的结构厚度，结合暖色室内与冷色雨夜。白天保留清晰日照与柔和居家感。

用户提供的 [玩偶三视参考](1.jpg)、[玩偶实物参考二](2.jpg)、[玩偶实物参考三](3.jpg) 决定玩偶形象。生成的室内概念图用于配色、材质、光影和陈设气质参考，不能替代125㎡面积要求、平面布局、88键钢琴规则或实际运行画面。概念图中的错位结构、重复家具、不合理楼梯与错误琴键不得照搬。

## 视觉完成度

高精细由可观察的轮廓、结构、接缝、倒角、材质和接触关系体现，不以高面数、高分辨率贴图或模型文件体积单独判定。重点资产在允许的最近观察距离仍应成立，远景和不可见背面允许合理简化。

奶白、暖米色与浅木构成大面积基础色，淡粉用于少量软装和设备细节。黑色主要用于五官、琴键及必要结构。屏幕、灯具与机箱发光不得把家具大面积染成高饱和霓虹色。

不强制三渲二明暗分层或明显描边。轮廓主要通过准确造型、明暗和材质对比辨认；使用风格化线条时应克制，不能吞并玩偶五官、琴键缝或设备细节，也不能随镜头变化明显闪烁。

画面应有主次和留白。手机整体构图重点表现上下层、挑空、主景窗与主题陈设；微小细节通过近景观察。不可通过堆满小物、提高反光强度或给所有家具增加发光边缘替代精细设计。

玩偶采用参考图中的普通微笑表情作为主要立体版本；其他表情可用于已要求的壁纸和相框。参考图片中的吊绳、标签和摄影背景不构成模型必做内容。绒毛质感可以通过适合手机的材质表达，不要求逐根几何毛发。

钢琴使用标准88键范围A0–C8，共52枚白键、36枚黑键。黑键遵循正确的两枚、三枚分组及两端排列；每键是可独立识别和运动的模型部件。音高映射为连续的MIDI音符21–108，A4采用440Hz基准，不能用重复贴图或重复音符凑足数量。

每枚琴键均须在模型上直接点按发声并产生对应按下、回弹反馈。局部放大后能够逐键辨认和点按，黑键不会同时触发下面的白键。验证琴键覆盖不要求把88键同时放大到一个手机画面内，也不增加演奏面板、自动切镜头或进入退出操作。

## 构图与空间关系

默认手机竖屏构图需同时辨认下层客厅、上层边缘与挑空，北侧主景窗构成环境背景。钢琴和电脑区不能同时被前景墙体遮住；用户放大和平移后能清楚观察两处重点资产。

电脑屏幕与机箱可视侧面向主要观察方向，琴键朝向开放区域。高柜集中靠完整墙面，临挑空栏杆尽量通透。镜头转向夹层下方时，楼板和前景遮挡应妥善处理，不能以隐藏整套家具解决遮挡。

通路、楼梯平台、琴凳周边与电脑椅活动范围不得重叠到无法合理使用。主通道约1.2–1.5米，椅子摆动和家具动效也不得侵入必要通行空间。此项通过尺寸与画面检查，不引入人物、碰撞或寻路系统。

白天的阳光应在地面、墙面或家具上形成方向明确的光斑与对应投影。夜晚的主照明、局部灯光与重点照明有清楚层级；机箱与屏幕只作点缀。两种状态都能分辨白色玩偶、沙发与钢琴的体积，奶白材质不过曝，暗部不糊成一片。

墙体、楼板、嵌入建筑的基础灯光、窗帘、地毯、玩偶、相框、杯子及零散装饰不计入上述分母；它们可以有动效，但不能用来补足家具覆盖。F14仅适用于同一连续橱柜中的内嵌设备，另行添加的独立家电需单独登记。

每种模式分别核验，不能将白天静止、夜间发光变化的灯同时算作两种模式的动效。需要同时满足自动播放、近景可观察、循环连续三个条件；静态发光、天气变化、镜头运动和昼夜过渡都不计入。

电脑椅左右转动幅度以中位两侧各4°–7°、完整往返周期10–16秒为基准；阅读摇椅以各1°–2°、周期7–12秒为基准。软装只在自由边缘产生约2–5毫米的轻动，周期8–15秒，主体不做呼吸式缩放。不同对象不得统一相位或全部同时起落。

循环扇机头摆角以两侧各12°–18°、周期12–20秒为基准；扇叶视觉速度应连续可辨，避免闪烁或明显反转错觉。净化设备的导风片以两侧各5°–10°、周期10–18秒为基准。摆钟摆动符合摆锤连接结构，不穿过外壳。

电脑壁纸每张停留12–20秒，电视画面停留18–30秒；过渡为0.6–1.2秒。两台屏幕各自运行，不同步闪切。动效需在60秒观察内可辨认，不能只靠数分钟一次的变化满足要求。

## 手机性能与资源目标

以下为项目验收目标，不代表已经测得或通过。移动端性能以iPhone 13的Safari与Pixel 6a的Chrome作为参考基准；实际验收应覆盖iOS Safari和Android Chrome，可采用实际可用、性能相近的手机，并记录替代机型与选择依据。系统、浏览器、渲染分辨率及画质设置以测试时记录为准，不能冒充未使用机型的实测，也不能用明显更高性能设备的结果证明基准性能已通过。

| 项目 | 目标与测量条件 |
| --- | --- |
| 持续运行 | 各昼夜模式稳定运行不少于60秒，平均帧率不低于30fps，95%的帧间隔不超过50ms；60fps作为提升目标 |
| 连续体验 | 连续运行10分钟，包含至少10次昼夜切换、观察与弹琴，不能崩溃、黑屏、持续降速或出现不断叠加的资源占用 |
| 首次进入 | 无缓存、下行20Mbps、往返时延约80ms条件下，12秒内出现可正常观察与点按琴键的完整首屏；实测同时记录真实网络情况 |
| 资源体积 | 首屏必要网络资源目标不超过20MiB，完整场景资源目标不超过50MiB，按实际传输体积统计 |
| 琴键响应 | 稳定加载并启用音频后，视觉反馈目标不超过100ms，声音响应目标不超过150ms；记录测量方式，不以主观描述替代精确延迟值 |

“完整首屏”要求主要房屋与家具资产、当前昼夜照明、当前屏幕图片、必需自动动效、触控观察及全部琴键已可用，不得以灰模、占位块或缺材质画面计时达标。尚未展示的后续轮播图片可继续加载，但必须在实际切换前就绪。

首次有效琴键点按仍需同时触发浏览器音频启用与发声，不能增加独立的开始演奏步骤。浏览器后台暂停、系统音量和设备省电状态等测试条件需记录。

未取得真实手机的检查结果时，对应项必须标记“未验证”；桌面设备模拟尺寸只证明布局与部分操作表现。目标未达成时提交实测值、影响和具体优化取舍，不能降低目标后直接宣称原要求通过。

## 优化质量底线

允许按主文档降低运行资产精度、贴图尺寸、阴影与反射成本，并保留高精度Blender源文件和原始生成图片。优先降低远景街景、不可见背面、微小装饰和过密表面纹理的开销。

必须保留玩偶识别特征、主要家具轮廓与厚度、机箱内部层次、88枚独立琴键及音高映射、楼梯与护栏结构、空间关系、昼夜核心光照差异，以及每模式超过半数家具的自动动效。

近景不得出现显著棱角、破面、UV拉伸、贴图糊化、法线接缝或穿插。轮廓与关键结构优先于不可察觉的表面小纹理；动态阴影与反光可以降级，但不能保留与当前光源或家具位置矛盾的旧状态。

每次明显降低精度都应记录实际瓶颈、涉及资产或效果、调整前后的资源与运行数据，并保留同设备、同视角、同昼夜状态的画面对比。不能只写“为了手机性能”而无具体依据；不得通过永久遮住上层、删除重点结构、停掉必需动效或整体模糊来换取指标。

## 交付证据与判定

交付应包含公开URL与版本、实际代码和依赖锁定文件、可编辑的Blender源文件、运行用模型、必要贴图和音源，以及资产名称与运行文件的对应清单。

生图记录应对应实际使用的每张相框图、电脑壁纸与电视画面，标明生成文件、最终纹理文件和场景使用位置。美术概念图与正式运行素材分别登记，不能用“已生成概念图”证明屏幕贴图已完成。

动效清单保留F01–F23编号，登记实际对象、日间结果、夜间结果及录屏位置；新增家具单列并重算覆盖率。琴键清单逐项登记88枚键的模型标识、音名、MIDI音符、直接点按结果及异常；程序映射检查与手机点按检查分别记录。

画面证据包含V01–V08规定取景及两种模式的动态录屏。性能证据标明设备、系统、浏览器、网络、测试时长、画质设置、测量方式和实测数据；在线访问、视觉质量、家具动效、琴键与性能分别判定“通过”“未通过”或“未验证”。

缺少真实运行证据、存在占位资产、手机看不清重点区域、琴键数或音高不符、家具覆盖不足、模型结构或光影明显错误，均不能判定最终验收通过。问题修复后以更新后的公开Site和对应版本证据复验。
