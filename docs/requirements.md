# Three.js 萌系 Loft 场景需求草稿

本文规定场景的内容、行为与交付要求；[精细度与验收标准](quality-standards.md)规定各项要求达到什么程度算合格；[美术参考说明](art-direction.md)说明参考图的用途和采用范围。三者共同构成实现依据，均描述最终应达到的结果，不作为开发步骤表。

## 项目目标

项目使用 Three.js 构建一个总使用面积为 125㎡的萌系 Loft 住宅，以手机浏览器为主要体验和验收平台。用户通过触控调整视角、平移和缩放，欣赏精致的空间与家具自动动效，自由切换阳光白天和温暖雨夜，并直接点按钢琴琴键弹奏。

场景不设置人物、可操控角色或角色漫游系统。家具以各自持续播放的动效呈现生活感，通用的家具点击开关、柜门开合、坐下起身等操作不属于本项目要求。钢琴保留直接点按琴键发声的操作。

整体采用高精细建模与萌系偏写实渲染，以已获用户认可的[雨夜概念图](references/loft-night-v1.png)作为质感方向。造型圆润可爱，材质细腻、光照自然，轮廓清楚。白天强调可见阳光与明亮柔和的居家感，夜晚强调经过设计的暖色室内照明与冷色雨夜街景。装修、玩偶、电脑桌整套设备与屏幕内容围绕用户提供的三张小熊玩偶参考图形成统一主题。

根据用户对雨夜参考图的最新反馈，三渲二分层色块和明显轮廓描边不再作为强制要求。可以采用克制的风格化处理，但应优先保留参考图中柔软布艺、真实材质层次与自然光影的表现。

## 移动端与视角操作要求

项目采用 mobile first 设计，手机竖屏作为默认进入方式，并兼容横屏观察。场景构图、必要控件、文字与点按目标应适合手机屏幕，不依赖电脑键盘、鼠标悬停或桌面窗口尺寸。电脑端可使用鼠标完成对应操作。

视角采用围绕室内观察目标的自由观察方式：单指拖动调整观察角度，双指捏合缩放，双指拖动平移观察位置。用户能够从整体观看切换到家具近景，也能查看上下层、钢琴、电脑桌和玩偶的细节。镜头不绑定人物，不采用角色跟随或步行操控。

初始构图应能辨认 Loft 的上下层、挑空与主题陈设。用户能够自行放大钢琴，无需点击钢琴整体进入专门视角，也无需演奏入口、退出按钮或独立弹琴界面。

墙体、楼板和前景家具不能使重点区域长期不可见。需要根据观察位置妥善处理遮挡，保证上层与夹层下方的空间都可看清；缩放和平移范围应避免镜头进入模型内部、丢失房屋或停留在无有效内容的位置。

点按琴键与视角手势必须明确区分。拖动、捏合及多指平移不能误触音符，轻点琴键时视角应保持稳定。手机横竖屏切换后，镜头构图与触摸命中位置仍需正确。

## Loft 面积与平面布局

总使用面积确定为 125㎡，按场景内上下层可使用楼面面积合计，下层约 80㎡、上层夹层约 45㎡。下层采用东西约 10 米、南北约 8 米的布局基准，整体高度按约 5.8 米设计。具体墙厚、家具尺寸与楼梯结构由建模设计协调，总面积与上下层关系保持一致。

以北侧作为主景窗方向，白天呈现阳光，夜晚呈现雨夜街景，入口位于东南侧。上层覆盖南侧约 45㎡；北侧约 35㎡为未铺设上层楼板的范围，包含客厅挑空与楼梯开口，不重复计入上层面积。初始观察方向以从东南侧看向室内与北侧窗景为构图参考，手机横竖屏分别调整取景。

## 萌系装修与参考图要求

装修以用户提供的 [多视角形体图](1.jpg)、[正面与绒面细节图](2.jpg)、[表情与比例图](3.jpg)为视觉基准。参考图中的主要特征是奶白色绒面、大头短身的圆润比例、小耳朵、短肢、黑色点眼与简洁嘴鼻，以及少量淡粉腮红和不同神态的表情。整体感觉应柔软、可爱、放松，保留简洁五官与饱满体积的识别度。

用户原图决定玩偶形体、五官与材质特征；补充生成的整体昼夜图和局部图用于确定配色、光影、材质与精细程度。面积、分区、尺寸、琴键数量及功能规则以文字需求为准，不能照搬生成图中的空间、结构或琴键错误。各图采用范围见[美术参考说明](art-direction.md)。

室内采用奶白、暖米色和浅木色作为主要配色，淡粉作为少量点缀，深灰或黑色用于表情、轮廓和细部。家具采用圆角、柔和曲面与有厚度的软包造型；玩偶主题通过靠垫、地毯、相框、屏幕壁纸和局部装饰呼应，保持空间留白和视觉层次。

家中至少摆放一只依据参考图制作的立体玩偶，位置应便于整体观看和放大观察，优先安排在客厅沙发或电脑桌附近。玩偶属于家居陈设，其模型应保留参考形体、五官与柔软材质特征。

电脑桌、机箱、显示器、键盘、鼠标、桌垫、座椅及周围装饰必须作为一套统一设计。设备外壳、软装、内灯和屏幕素材应共享萌系配色与图案语言，兼顾可爱感与精致结构。

## 建模精度与萌系偏写实光影要求

房屋、家具、玩偶与电脑设备需要保持高精细建模观感。细节应体现在轮廓、倒角、接缝、软包厚度、布料褶皱、琴键结构和电脑内部部件上。放大观察时，关键结构仍需清晰、自然。

核心资产的具体结构与近景检查项按[精细度与验收标准](quality-standards.md)执行。精细度通过最终 Site 中的整体、近景与连续转动观察判断；面数高、贴图大、源文件存在或生成脚本运行成功，均不能单独证明画面合格。

画面应具有明确的明暗组织、自然柔和的光照过渡和清楚稳定的物体轮廓。主要通过几何造型、材质差异和光影区分物体；如局部使用辅助描边，应细而克制。镜头变化时避免边缘明显闪烁、断裂或细节糊成黑块，不要求统一的黑色外描边。

材质层次应细腻但简洁。绒面、布料、木材、金属、玻璃和陶瓷应通过适量纹理、柔和明暗及高光差异辨认。玩偶与软装强调柔软质感，电脑与钢琴保留精致的硬质结构，各自融入同一套萌系偏写实画面。允许真实感的纹理、反射与柔和阴影，但不追求污渍、磨损或过密纹理。

夜晚室内以温暖柔和的灯光为主，窗外为冷色雨夜街景。窗边、玻璃和附近家具应体现暖冷光色交汇；白天以自然日照为主，突出萌系材质与柔软体积。两种状态的暗部均应保留辨识度，重要陈设、琴键和屏幕内容应清楚可见。

雨夜街景需要有湿润的地面、积水及玻璃反光，体现街灯与窗光的映照。反射、雨水与高光共同构成夜景层次，室内各材质的反光强度应与其用途和整体萌系氛围协调。

## 昼夜切换与灯光设计要求

场景必须提供适合手机点按的白天、黑夜切换控件，明确显示当前状态，不遮挡主要画面或琴键。初始采用黑夜模式，用户可随时切换至白天并切回。白天采用有阳光的明亮天气，黑夜保留既定的雨夜氛围。

切换需要同步改变天空与窗外街景、日照、室内灯具亮度、屏幕与机箱发光、反射和天气动效，呈现两套完整的光照氛围。过渡应柔和，不出现明显闪白、全黑或光影状态错配。切换保持当前镜头位置与缩放，不重置家具动效或壁纸轮播，不中断正在衰减的琴音，也不影响继续点按琴键。

### 白天的阳光表现

白天必须能清楚感受到阳光进入住宅。阳光从主景窗斜向照入，在地板、墙面或家具上形成可见的受光区域，并呈现窗框、栏杆与家具对应的投影。仅调亮背景或整体环境亮度不能满足阳光表现要求。

日照重点覆盖客厅、钢琴附近与部分上层空间，形成有方向、有层次的明暗关系。夹层下方通过柔和的环境补光保留细节，玩偶与奶白家具应有立体感，避免白色材质过曝成一片。室内装饰灯可关闭或减弱，电脑与屏幕仍保持可辨认的运行表现。

### 黑夜的分区灯光

黑夜照明必须围绕既定平面布局进行设计，包含基础照明、使用位置的局部照明和突出陈设的重点照明。灯具造型与奶白、圆润的装修主题统一，亮度分布有主次，形成温暖、安静而精致的生活感。

| 区域 | 夜间灯光设计 |
| --- | --- |
| 客厅与挑空 | 柔和主灯或间接光建立空间亮度，沙发侧落地灯形成局部暖光，保留挑空上部的明暗层次 |
| 钢琴与玩偶 | 用克制的重点照明突出琴键、琴身曲面与玩偶五官，附近墙地面有自然的光照过渡，奶白表面不过曝 |
| 电脑桌 | 桌面灯提供清楚的局部照明，机箱使用与主题协调的柔和内灯，屏幕发光作为局部点缀，保持壁纸可读 |
| 餐厨 | 餐桌上方暖色灯光形成聚焦，橱柜下方照明表现台面与沿墙结构，和客厅有自然亮度衔接 |
| 楼梯与平台 | 低亮度踏步灯或侧墙灯表现楼梯走势、转角与上层边界，避免刺眼的连续高亮灯带 |
| 卧室与阅读区 | 床头灯和阅读灯营造安静的小范围暖光，收纳区保留柔和间接照明，与下层形成层次 |
| 玄关与卫生间 | 使用简洁、柔和的局部照明，让入口和小空间清楚可辨，并保持统一色调 |

灯光必须在周围物体、墙面和地面上形成可观察的照亮范围、明暗渐变及必要的阴影，灯具发亮的外观应与实际照明对应。主要照明保持稳定，少量装饰灯的轻缓动效不能打乱整体亮度设计。冷色窗外环境与暖色室内灯光共同突出住宅的层次。

两种模式都应保持清晰轮廓和统一材质风格。白天的日照投影、夜晚的分区照明及反光方向应分别与各自光源对应；具体渲染方式可按手机性能选择，但不能把昼夜差异简化为整体亮度变化。

## Blender 资产要求

房屋结构、家具、钢琴、玩偶、电脑整套设备、相框和电视等主要三维资产必须通过 Blender 建模，保留可编辑的 `.blend` 源文件。正式资产不得以 Three.js 代码生成的基础几何体拼装替代 Blender 模型。Three.js 负责运行时展示、视角操作、家具动效、材质渲染与琴键声音响应。

模型需要满足各自动效与点按要求。电脑风扇、椅子活动部分、钢琴各个琴键等应能独立运动或识别，部件命名、层级、尺寸单位与活动轴心应清楚一致。

模型应有适合实时展示的网格结构、正确的表面朝向和稳定的明暗表现。家具与房屋的尺度应协调，循环动效不应造成明显穿插、漂移或结构脱离。

可以使用 Blender 灰模验证分区、家具尺度、留白、楼梯结构与镜头可见性；正式交付仍需满足既定的精细造型与装修要求。

## 材质贴图与 Shader 要求

使用图像或烘焙贴图的表面应具备正确的 UV 映射，保证比例、方向、清晰度和接缝质量。相框、电视和电脑显示器的画面区域必须能够独立配置与替换贴图，不影响边框、机身及其他材质。

贴图精度应与观察距离及视觉重要性匹配，放大可见的玩偶五官、琴键和主题图像需保留关键细节。材质按需提供颜色、法线、粗糙度、发光与遮蔽等信息，保持细腻但简洁的层次。

烘焙按需采用，可承载静态表面细节、环境遮蔽和适合固定保存的光照。烘焙使用的 UV 不得出现非预期重叠或边缘串色；家具摆动、风扇旋转和灯光变化时，不应残留与当前表现矛盾的固定阴影或亮斑。烘焙光照需要与昼夜状态匹配，切换后不得保留上一模式的日照光斑、灯光亮斑或阴影。

Shader 与相关渲染处理需要在 Three.js 中实现自然明暗、柔软布艺、不同材质的高光及雨夜反光等目标表现。可使用适合移动端的标准材质与必要的定制 Shader，不要求为了形式编写整套自定义着色器。需要随视角或动效变化的效果应在运行时合理响应，材质复杂度以手机实际运行效果为约束。

## 家具自动动效要求

大部分家具应具有各自可观察的自动动效，场景加载完成后无需用户逐件点击启动。动效可以表现为部件运动、材质变化、局部灯光变化或内容轮播，幅度轻柔、节奏舒缓，增强萌系住宅的生命力。

家具动效按主要家具整体对象统计，白天和黑夜均应有超过半数的主要家具具备可观察的自身动效；墙体、地板和零散装饰小物不计入家具数量。同一家具上的多个动态部件只计为一个家具对象。统一的雨景、镜头运动、昼夜切换或全局灯光变化不能代替家具自身动效，静态亮着的灯也不能单独算作动效。

家具及对应动效需要列入交付清单。主要动效设计采用以下方向：

| 对象 | 动效表现 |
| --- | --- |
| 电脑主机 | 透过机箱可观察内部结构，以风扇持续转动和柔和内灯表现运行状态；内灯可有轻缓变化，避免强烈闪烁 |
| 电脑显示器 | 自动持续轮换符合装修主题的壁纸，切换自然，单张画面停留时间足够看清 |
| 电脑椅或休闲椅 | 无人操作时缓慢左右摇晃或小幅转动，动作平稳，不侵入主通道或穿过桌体 |
| 电视 | 自动轮换与主题协调的生成画面，与电脑屏幕保持各自自然的切换节奏 |
| 灯具 | 依据昼夜模式启用或调整亮度；夜间部分装饰灯可有细微亮度变化，主要室内照明保持稳定和舒适 |
| 沙发与床铺 | 可通过靠垫或毯角的轻微起伏呈现柔软、安静的动感，主体保持稳定 |
| 时钟及其他合适陈设 | 按物体特点补充指针运动等自然动效，避免所有物件同步摆动 |

显示器持续轮播与椅子慢速左右摆动属于明确的表现要求。其他家具动效可结合实际造型细化，但必须保证整体覆盖范围，不能只让少数设备有动效。

完整家具统计、昼夜动效与可见性按[精细度与验收标准中的清单](quality-standards.md#家具清单与自动动效覆盖)核验。静态家具也必须登记，不能只选取有动效的物件计算比例，或拆分一个家具的部件凑数。

动画循环应衔接自然，没有明显跳变和累积位置偏移。停止操作镜头时，用户仍能观察到家具的不同活动。动效之间应有节奏差异，画面保持安静、精美，琴键和屏幕内容仍需清楚可辨。

## 钢琴直接点按与声音要求

家中配置一台融入装修主题的奶白色小型三角钢琴与配套琴凳。琴身、黑白琴键和踏板等主要结构应完整，琴键朝向开放、便于观察的区域。

钢琴采用标准 88 键布局，包含 52 枚白键与 36 枚黑键，音域为 A0–C8。低音到高音排列、黑键的两枚与三枚分组及各键对应音高必须正确，不能仅命名 88 个部件而重复映射少量音高。踏板需建模，不要求踏板演奏或多点和弦功能。

模型中呈现的每一枚黑键和白键都必须能够直接点按，并发出对应音高。手机使用手指轻点，电脑使用鼠标点击；连续点击不同琴键能够弹奏旋律，不设置电脑键盘快捷键映射。

用户自行使用通用视角操作放大和查看琴键。无需点击琴身激活、自动切换演奏镜头、弹出独立琴键面板，也不设置进入或退出演奏状态。琴键始终遵循相同的直接点按规则。

每次有效点按应有及时的声音和对应琴键的按下、回弹反馈。停止点按后声音自然衰减，连续弹奏不应出现明显爆音、异常延音或失控叠音；点按黑键时不得误发下方白键的声音。

声音可以使用 Web Audio API 合成，也可采用适合手机加载的钢琴采样或其他合适方案，以钢琴音色、响应速度与资源体积为依据。首次有效琴键点按应能启动声音，不增加额外的“进入演奏”操作。页面可保留简单的全局音量或静音控制。

## 屏幕与相框画面要求

相框中的图片、电视画面和电脑显示器壁纸必须实际调用生图技能制作，并作为贴图应用到对应模型上。图像应延续参考玩偶的奶白、圆润、简洁表情与萌系日常主题。

电脑壁纸可采用自嘲熊表情包风格或与玩偶主题协调的趣味画面，表情与构图在手机画面和放大观察时应清楚可辨。不同屏幕和相框的内容可以有变化，但色彩、细节密度和情绪保持统一。

电脑显示器至少提供 6 张不同内容的壁纸，涵盖发呆、困倦、努力和轻松等日常表情；电视至少提供 4 张与家居主题一致的日常插画；相框至少配置 3 幅不同构图的主题画。各组允许共享角色与配色，不以同图改文件名、轻微调色或反复切换同一图充数。画面以图像表达为主，不依赖小字笑话；使用文字时需清晰、无乱码。

每张电脑壁纸停留约 12–20 秒，电视画面停留约 18–30 秒，采用约 0.6–1.2 秒的柔和过渡，二者节奏错开。最终生成图片、提示词和对应模型的贴图映射须留存；本次补充的美术概念图不能代替这些运行时贴图资产。

屏幕需要持续轮换生成图片，切换时避免空白、明显卡顿或比例跳变。画面不得明显拉伸、错误裁切或模糊；屏幕亮度应适应昼夜环境，白天清楚可读，夜晚不过亮或破坏室内暖光。轮播以生成图片为内容，不要求视频播放功能。

## 昼夜环境与天气动效要求

黑夜模式下，窗外雨水应持续可见，结合玻璃雨滴滑落、地面涟漪或湿润反光的轻微变化构成雨夜氛围，具体组合根据手机运行表现选择。白天模式关闭持续降雨与玻璃雨滴动效，窗外呈现有阳光的日间环境，街灯与地面反射相应调整，避免残留不匹配的夜景效果。

可结合陈设补充热饮蒸汽、窗帘边缘轻摆、玩偶轻微晃动等生活细节。装饰动效不将玩偶变为可操控角色，也不引入人物行为或家具操作流程。

环境动效与家具动效共同存在，不能遮挡主要陈设、干扰琴键点按或造成过强的画面噪声。循环需要连续自然，并保持不同对象之间的节奏差异。白天和黑夜均应保持主要家具动效与屏幕轮播，天气变化不重置场景内容。

## Three.js 运行与资产交付要求

运行用三维资产优先采用 glTF 2.0 格式及其二进制封装 GLB，并保留 Blender 源文件与必要的原始贴图。加载后应保持正确的比例、朝向、部件层级和材质关系，动态部件与琴键能够独立访问。

Blender 与 glTF 的材质表达存在差异，不能假定完整节点材质效果会随模型自动移交。相关限制参见 [Blender glTF 导出器说明](https://github.com/KhronosGroup/glTF-Blender-IO/blob/main/docs/blender_docs/scene_gltf2.rst#exported-materials)。布艺质感、玻璃、屏幕、光照和湿润反光应以 Three.js 实际呈现为准。

模型、贴图、家具动效、昼夜灯光与环境效果、触控镜头及钢琴声音必须在同一场景中共同工作。最终验收以公开 Site 的手机浏览器体验为准。

交付同时包含可运行源码、依赖锁定文件、构建说明、实际使用的 `.blend` 与运行模型、原始生成图片及其提示词、资产来源与运行资源对应表、家具清单和验收记录。仅提供制作脚本、概念图、文档或未部署的本地效果，不视为场景完成。

## 移动端性能与资源要求

画面精度与运行预算以手机为主要依据。自动动效、屏幕轮播、当前昼夜的光影与天气、镜头操作和琴键发声同时存在时，应保持稳定、连续的体验，琴键反馈及时。反复切换昼夜不应造成明显卡顿、资源持续堆积或运行中断。

模型面数、材质数量、贴图尺寸、渲染分辨率、透明效果、反射和阴影等开销需要受到控制。应关注首次加载、图片切换以及持续观看时的运行表现，不以桌面电脑流畅代替手机验收。

构建、资源上传、Site 部署或手机运行受限时，允许适当降低运行模型精度、贴图分辨率、材质复杂度和部分效果质量。优先简化远景与次要细节，保留高精度 Blender 源文件和原始贴图。

精度调整必须保留参考玩偶的识别特征、主要家具造型、萌系装修、清晰轮廓、白天阳光与夜间分区灯光，并保持家具主要动效、屏幕轮播、昼夜切换、触控观察和全部琴键点按功能。实际取舍需要记录，并在公开 Site 复验。

验收需要记录代表性手机型号、操作系统、浏览器、屏幕方向、渲染设置及网络条件。目标帧率、可接受加载时间和资源体积控制要求见[精细度与验收标准](quality-standards.md)。目标为设计约束，实测前不得表述为已经达到；缺少真机条件时应保留未验证状态。

## 公开 Site 部署与在线验收要求

项目必须部署到 Sites，并将验收 Site 设置为公开访问。验收者能够通过公开 URL 直接进入场景，无需登录部署者账号、加入工作区、申请权限或配置本地环境。

每个提交验收的版本需要提供公开 URL、版本或发布时间、触控操作说明、家具动效清单及已知问题。模型、贴图、音源和其他必要资源应在线完整提供，不依赖开发者本机路径或本地服务。

交付方必须实际访问公开 Site，使用未登录部署者账号的新会话检查首次进入和刷新后的加载表现。核心验收需要覆盖真实手机浏览器的竖屏与横屏体验；桌面模拟手机尺寸仅作为辅助。验收者通过同一 URL 体验与复核。

| 验收项 | 访问 Site 时的检查内容 | 通过条件 |
| --- | --- | --- |
| 公开访问与加载 | 在手机新会话打开公开 URL，等待加载并刷新 | 无需访问授权，模型、贴图和音源资源可用，场景与触控正常 |
| 移动端观察 | 单指拖动、双指缩放与平移，查看上下层及夹层下方，切换横竖屏 | 构图适合手机，主要空间可见，镜头不丢失场景，不依赖键盘或悬停 |
| 布局与萌系装修 | 查看各区关系、通路、钢琴、电脑桌及参考款玩偶 | 面积与分区符合要求，家具精美协调、通路清楚，玩偶和电脑整套主题统一 |
| 萌系偏写实与昼夜画面 | 分别观察白天和黑夜的近景轮廓、布艺、硬质表面、窗边光影与反射 | 两种状态风格统一、材质可辨，具备参考图的柔软体积和细腻光影，无明显缺贴图、过曝、轮廓闪烁或渲染异常 |
| 白天阳光 | 查看主景窗附近的地面、墙面、钢琴及上层受光区域 | 能看清阳光进入室内的方向、光斑与对应投影，夹层下方仍保留细节，日间天气表现一致 |
| 黑夜灯光设计 | 查看客厅、钢琴、玩偶、电脑桌、餐厨、楼梯和上层各区域 | 照明有主次和分区，灯具实际照亮周边，重点陈设突出，暖色室内与冷色雨夜形成对比 |
| 昼夜切换 | 在手机上反复切换，保留放大后的视角并继续观察动效、点按琴键 | 光照、天空、雨景及发光材质协调变化，镜头不重置，动效和琴键功能持续正常，无明显闪屏或旧光影残留 |
| 家具自动动效 | 不点击启动，按家具清单观察各自动效和循环 | 大部分家具有独立动效，显示器持续换壁纸，椅子缓慢摆动，动作无明显穿插和跳变 |
| 钢琴逐键发声 | 自行放大钢琴，逐一检查黑白键，连续点按并停止；同时验证视角手势 | 每键对应正确音高和视觉反馈，无演奏入口出口，手势不误发音，声音及时且自然收尾 |
| 持续运行与性能 | 在约定手机上分别运行白天和黑夜场景，反复切换并同时观察动效、操作镜头和弹琴 | 两种模式达到约定指标，无影响体验的资源加载、Shader 编译、声音或脚本错误 |

在线验收记录应包含 URL、版本、手机与浏览器环境、网络条件、昼夜模式、检查结果及必要的截图或录屏，结果区分通过、未通过和未验证。问题需要记录位置、触发操作、预期和实际表现，修复后在更新后的公开 Site 复验。

家具动效覆盖按完整主要家具清单核验，固定视角与动态检查按[精细度与验收标准](quality-standards.md)执行。性能以记录的设备、渲染设置与网络条件下实测结果判断；缺少验证环境或数据时不得直接判定通过。部署成功仅代表上线完成，验收通过仍需实际访问和操作记录支持。

Blender 建模与生图素材来源另以可编辑源文件、生成记录、生成图片及其与线上资产的对应关系核验。制作资料与线上效果共同支撑交付结果。

## 实现自主权与验收记录

平面布局、萌系配色、手机触控方式、无人物设定、家具自动动效、88 键钢琴直接点按、昼夜切换及两种灯光氛围已经确定。几何细化、音源、Shader、贴图制作和资源优化方式由实现者依据本需求自主选择，不需要逐件等待用户设计。

实际采用的手机型号、系统与浏览器版本，最终家具对象名称及模型节点，贴图资产文件名、资源体积、测量数据和公开 URL 在实现交付时据实填入。设计要求与验收证据分开记录；参考图或文档尚不能代表已经完成的模型、动效或线上场景。
